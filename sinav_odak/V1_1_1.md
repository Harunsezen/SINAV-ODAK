## 1. API ZİNCİRİ

### 1.1 Ne bulundu

`targetSdk` sabit değildi, `flutter.targetSdkVersion`'a bırakılmıştı ve
Flutter 3.24.5'te o değer **34**:

```
/opt/fl/flutter/packages/flutter_tools/gradle/.../flutter.groovy:56
    public final int targetSdkVersion = 34
```

Yani uygulama API **34** hedefliyordu. Play, 31.08.2025'ten beri en az
API 35 istiyor; **31.08.2026'dan itibaren API 36**. Flutter'ın
varsayılanına bırakmak uygulamayı güncellenemez hâle getirirdi.

### 1.2 Ne yapıldı

```
compileSdk  35 → 36     (Android 16)
targetSdk   34 → 36     artık SABİT, flutter.targetSdkVersion'a bağlı değil
minSdk      21          DEĞİŞMEDİ — J7 Prime sınıfı cihazlar kalıyor
desugaring  açık        DEĞİŞMEDİ (flutter_local_notifications şart koşuyor)
AGP        8.6.0 → 8.9.1
Gradle      8.9  → 8.11.1
```

`minSdk 21` bilinçli: `java.time` desugaring 21'den itibaren çalışıyor,
yani bildirimler için engel değil.

Manifest'e **hiç dokunulmadı** — `USE_EXACT_ALARM`,
`SCHEDULE_EXACT_ALARM`, `RECEIVE_BOOT_COMPLETED`, AdMob meta-data ve boot
receiver aynen duruyor.

### 1.3 ⚠️ AGP yükseltmesi bu ortamda DOĞRULANAMADI

Gradle wrapper'ın yeni sürümü **doğrulandı**: 8.11.1 indi, çalıştı,
`settings.gradle`'ı ayrıştırdı.

AGP 8.9.1 **doğrulanamadı**. Sebep ortam kısıtı, kod değil:

```
$ curl https://dl.google.com/dl/android/maven2/.../maven-metadata.xml
curl: (56) CONNECT tunnel failed, response 403

$ curl "$HTTPS_PROXY/__agentproxy/status"
"detail": "gateway answered 403 to CONNECT (policy denial...)",
"host": "dl.google.com:443"
```

Google Maven proxy politikasıyla engelli, dolayısıyla **AGP'nin hiçbir
sürümü** burada çözülemiyor — 8.9.1 de, önceki 8.6.0 da.

**8.9.1 neden seçildi:** compileSdk 36'yı tanıyan ilk AGP hattı 8.9;
AGP 8.9 de Gradle 8.11.1+ istiyor. İkisi birlikte yükseltildi.

**Sizin makinenizde ilk iş bunu doğrulayın:**

```
cd sinav_odak/android && ./gradlew --no-daemon help
```

Sürüm hatası verirse Android Studio doğru numarayı söyler; geri alma
tek satır:

```
android/settings.gradle              → version "8.6.0"
android/gradle/wrapper/...properties → gradle-8.9-all.zip
android/app/build.gradle             → compileSdk = 35, targetSdk = 35
```

`targetSdk 35` Play'in 31.08.2026 tarihine kadarki eşiğini karşılar.

## 2. YATAY MOD

### Kilit manifest'te DEĞİLDİ

Manifest'te `screenOrientation` hiç yoktu — kilit Dart tarafındaydı:

```dart
// lib/main.dart:27 (KALDIRILDI)
await SystemChrome.setPreferredOrientations([DeviceOrientation.portraitUp]);
```

Tek bir satır yüzünden tablet, Chromebook, katlanır ve masaüstü/XR
pencerelerinde uygulama yan çevrilemiyordu.

Kaldırmak **güvenli olduğu ölçüldükten sonra** yapıldı (§3);
`configChanges` zaten `orientation|screenSize|screenLayout` içeriyordu,
yani yön değişiminde Activity yeniden yaratılmıyor.

`SystemUiMode.edgeToEdge` duruyor.

## 3. EVRENSEL EKRAN — 140 test

`test/qa/responsive_test.dart`: her ekranı her boyutta **dikey ve yatay**
kurup `RenderFlex overflowed` hatası aranıyor.

### Matris

| Boyut (logical) | Temsil ettiği |
| --- | --- |
| 320×568 | en dar gerçekçi Android |
| 360×640 | **Galaxy J7 Prime** (720×1280 fiziksel, dpr 2) |
| 411×731 | tipik modern telefon |
| 480×853 | büyük telefon |
| 480×1040 | S26 Ultra sınıfı uzun yüzey |
| 800×1280 | tablet |
| 768×1366 | Chromebook |
| 1080×1920 | monitör / XR geniş pencere |

8 boyut × 2 yön × 7 ekran = **112** + 28 insets = **140 test**.

> **Neden logical piksel:** düzeni belirleyen ölçü bu. Fiziksel çözünürlük
> cihaz piksel oranıyla değişir, düzen değişmez. J7 Prime'ın 720×1280'i
> dpr 2'de 360×640 logical demek.

### Bulunan taşma — 1 tane

```
kucuk-320 · dikey (320x568) hedefler
  A RenderFlex overflowed by 14 pixels on the right.
```

Hedef kartındaki ilerleme satırı iki `Text`'i yan yana koyup ikisinin de
doğal genişliğini istiyordu ("120 / 240 dakika" + "%50"). 320 px'de
sığmıyor.

**Düzeltme — sabit piksel yok:** sol taraf `Expanded` + `ellipsis`,
yüzde/"Ulaşıldı" hiç kırpılmıyor (asıl bilgi o).

Diğer 111 kombinasyon ilk koşuda temizdi.

### Edge-to-edge / insets — 28 test

Android 15+ uygulamayı sistem çubuklarının altına çiziyor; güvenli alan
`MediaQuery.padding` ile geliyor ve **düzeni daraltıyor**. Dar ekranda
taşmayı tetikleyecek yer tam burası.

`tester.view.padding` ile gerçek pay simüle ediliyor:

- dikey: `top: 48, bottom: 48` (durum + gezinme çubuğu)
- yatay: `left: 48, right: 48, bottom: 24` (çentik + jest çubuğu)

En dar iki cihazda (320, 360) yedi ekranın hepsi, iki yönde. **Hepsi
temiz.**

## 4. AAB ÜRETİLEMEDİ

```
$ flutter build appbundle --release
[!] No Android SDK found. Try setting the ANDROID_HOME environment variable.
```

**İki ayrı engel var, ikisi de bu ortamdan kaynaklı:**

1. **Android SDK yok.** `ANDROID_HOME` boş, `~/Android/Sdk` yok. Kurmak da
   mümkün değil: `dl.google.com` proxy tarafından engelli (§1.3).
2. **Production AdMob app ID elimde yok.** `-Padmob_app_id=ca-app-pub-…~…`
   olmadan derleme Google **test** kimliğiyle çıkar; o AAB canlıya
   gitmemeli. `app-ads.txt`'teki `pub-6172662947666489` *yayıncı* kimliği,
   AdMob *uygulama* kimliği değil.

Sahte bir çıktı üretmektense boş bırakıyorum. **Sizin makinenizde:**

```
flutter build appbundle --release \
  -Padmob_app_id=ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY
```

`android/key.properties` yoksa Gradle uyarı basar ve AAB debug anahtarıyla
imzalanır — o dosya Play'e yüklenemez.

## Testin göremediği iki kusur

`responsive_test` "taşma yok" diyordu ve doğru söylüyordu. Ama taşmayan
bir düzen yine de kullanılamaz olabilir:

| # | Nerede | Kusur |
| --- | --- | --- |
| 1 | Yatay telefon 640×360 | **Birincil eylem ekranın dışında.** Alt çubuk kısa yüksekliğin ~%25'ini yiyor; "Oturumu Başlat" gezinme çubuğunun altında kalıyordu. Taşma hatası YOK — sadece görünmüyordu. |
| 2 | Geniş ekran 1920×1080 | **İçerik kenardan kenara yayılıyor.** Tek düğme ~1900 px genişliyor, satırlar okunamayacak kadar uzun, alt %40 bomboş. |

İkisi de yalnızca çıktıya **bakınca** görüldü.

## Düzeltme — uyarlanabilir kabuk

`AppShell` tek yerden ikisini de çözüyor:

```dart
final useRail = constraints.maxWidth >= 640 &&
                constraints.maxWidth > constraints.maxHeight;
```

- **Yatay ve geniş yüzey** → `NavigationRail` (yan ray). Dikey alanı geri
  veriyor; yatay telefonda birincil eylem tekrar ekranda.
- **Diğer her şey** → `NavigationBar` (alt çubuk). Tablet **dikey**de
  (800×1280) alt çubuk kalıyor — genişlik yeterli ama yüzey dikey.
- İçerik her durumda **en fazla 720 px** ve ortalanmış. Sabit düzen ölçüsü
  değil, okunabilirlik sınırı; dar ekranda hiçbir etkisi yok.

Ray **kaydırılabilir**: 5 hedef + etiket 360 px yüksekliğe sığmıyor ve
`NavigationRail` kendiliğinden kaydırmıyor — `SingleChildScrollView` +
`IntrinsicHeight` + `minHeight` kalıbı kullanıldı.

Bu aynı zamanda Play'in büyük ekran kalite kılavuzunun önerdiği desen.


**35'e dönüş yok.** Hiçbiri geri alınmadı.

## Tabletler 1280×800 → 1920×1200

Telefon görselleri pixelRatio 3.0 ile üretiliyordu (1080×1920), tabletler
1.0 ile (1280×800). Aynı listelemede tabletler gözle görülür şekilde
yumuşak kalıyordu.

Yüzey aynı (1280×800 logical), **pixelRatio 1.5** → 1920×1200 — 10" tablet
standardı. Yeniden boyutlandırma yok: `toImage` ağacı doğrudan hedef
çözünürlükte çiziyor, metin gerçekten keskin.

## Tek üretici: `test/qa/store_shots_test.dart`

Vitrindeki **altı** görüntünün tamamı artık tek dosyadan çıkıyor:

| Dosya | Yüzey | ratio | Çıktı |
| --- | --- | --- | --- |
| `screen_1..4.png` | 360×640 | 3.0 | 1080×1920 (9:16) |
| `tablet_1..2.png` | 1280×800 | 1.5 | 1920×1200 (8:5) |

Daha önce telefon üreticisini "kod değişikliği YOK" kuralı gereği
silmiştim; o kural bu turda geçerli değil ve `store_assets/` zaten

yenilenebilmesi gerekiyor:

Tablet yüzeyi yatay ve geniş olduğu için `AppShell` **yan rayı** seçiyor;
